# zg 关系查询验证集（G0）

这是固定的规则构图夹具及后续对照协议，尚无图检索效果或性能结果。代码 8 题、文档 8 题；没有代码与文档关联题。题目和证据标签位于 `corpus/` 之外，构建索引时仅选择 `corpus/`。

- `sources.json` 固定文件路径、SHA-256、代码模块命名空间与模块路径。
- `questions.json` 固定问题、预期引用状态、目标和必需证据的 `[start,end)` UTF-8 范围与原文。标签是本轮编写的初始预期，待人工复核；自动测试核对标签对应的字节和规则结果，不等同于人工质量验收。
- 负例也保留证据：参数遮蔽、动态接收者、文档指向代码文件、缺失锚点。
- 入站问题必须覆盖所有标注引用；D06 要求完整的两步证据路径。G1 测试只验证基础边，不声称入站查询、路径执行或补充内容已经可用。

## 固定对照协议

协议为 `zg-graph-eval-v1`，独立于既有 SWE-QA20，后者保持原样。

G4 使用同一构建的普通搜索与显式开启图增强两组。模型固定为 `local/potion-code-16m-v2`、CPU，检索模式固定 hybrid，limit=10、preferSymbol=false、autoUpdate=false、freshness=eventual。每题 5 次，前 4 次记录延迟，第 5 次记录质量；普通召回列表必须记录并核对两组相同。图增量上限为 5 种子、2 跳、20 补充节点、100 条关系检查、16 KiB 附加证据，两组最终输出统一最多 32 KiB UTF-8。构建与查询在相同机器、同一来源清单上运行。

运行前必须在报告中冻结实际 Git 提交和未提交差异摘要、执行文件摘要、模型/分词器摘要、graphdb/zvec 原生版本、硬件、请求期限和完整请求。G2/G3 尚未交付，当前不能生成这个运行报告，也不把组件测试标成查询增益。若模型不可用或协议需要调整，发布新的协议版本，不能在看到质量结果后修改旧标签。

分别报告两组的完整证据覆盖、有效引用比例、无关补充量、输出字节、查询 p50/p95、构建/增量时间、RSS 和磁盘增量。负例要求正确拒绝或诊断。代码、文档各自验收；不能用简单夹具的通过率宣称在真实仓库上有收益，真实仓库验证集须另行冻结。先前本地开发档规模/性能门仍独立执行，不由本夹具替代。

## 运行 G1

```bash
cd rust
cargo test --locked -p zg-engine --features knowledge-graph --test graph_facts -j 14
cargo run --locked -p zg-engine --features knowledge-graph --example graph_facts -j 14
```

示例只输出候选事实，没有持久化、Embedding、索引写入或模型加载。不要把整个仓库作为该验证集的语料输入，以免索引题目、标签和 README。
