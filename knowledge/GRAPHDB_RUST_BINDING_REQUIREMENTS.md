# graphdb Rust binding 接入要求

本文件是 zvec-grep 消费上游 binding 的需求，不实现或指定 graphdb 仓库的 FFI 技术、crate 名称或发布方式。当前本仓库没有 `zg-graphdb` crate。

## 职责

graphdb 仓库维护原生构建、链接/分发、Rust 安全句柄、类型转换、事务和底座错误。`zg-knowledge` 维护来源身份、修订、操作/尝试、回执、知识选择、发布与恢复核对；这些业务规则不下沉到 binding。

只在 `zg-knowledge` 内实现适配器，满足内部图存储契约。当前 G2 采用具体数据库与连接会话边界，调整或移除未使用的通用 `GraphStore` 端口，不另建多后端框架，见 [G2 实施计划](G2_IMPLEMENTATION_PLAN.md)。生产依赖锁定上游实际版本或提交，不能把本机绝对路径、Python wheel 或子进程作为运行前提。

## 最小能力

| 能力 | 接入要求 |
| --- | --- |
| 打开与关闭 | 显式可写/只读、TP 持久化配置、超时/中间行/保留版本预算；不隐式升级知识库 |
| 生命周期 | 数据库、独立连接、事务与结果的拥有/借用关系明确；关闭与正在执行的原生调用协调 |
| 参数与结果 | 参数化 Cypher；列名与行；null、bool、i64、有限浮点、UTF-8 字符串，以及实际查询需要的列表/映射；不得通过字符串插值绑定业务值 |
| 读事务 | 显式 READ ONLY 事务固定视图，不能把默认 begin 当成只读事务 |
| 写事务 | 明确 begin/commit/rollback；未完成事务释放时安全回滚；失败不能留下部分业务效果 |
| 并发 | 连接的线程安全边界明确；允许旧只读视图与新写发布共存，不能未经验证地添加 Send/Sync |
| Schema | 在空闲连接上执行 DDL，与业务写事务分开；不假定 ALTER/DROP/MERGE |
| 错误 | 区分关闭、只读、冲突、预算、超时、取消、普通存储失败及 CommitOutcomeUnknown；不能只通过消息字符串推断提交状态 |
| 原生运行 | 无 Python 运行要求；构建变体与原生库来源可记录，能在同一进程中与宿主 zvec 链接运行 |

不要求 binding 内实现异步调度、自动重试、operation_id、更正、跨库事务或知识发布。阻塞调用由知识层的有界执行资源承载。

## 本仓库接入门

1. 在实际上游 binding 上验证参数往返、DDL、写事务回滚、显式只读视图和关闭重开。
2. 验证提交后在新只读事务中的实际可见性，以及旧读视图与写发布并存。
3. 验证提交结果未知的结构化错误映射；适配注入与真实底座故障分别记录。
4. 端到端接通来源/修订/回执及候选发布，验证来源竞争、attempt fencing、取消和恢复核对。
5. 执行迁移矩阵中仍待 graphdb 接入的案例；通过后才宣布 Rust Phase 1–3 行为等价。

当前 `graph.rs` 仅保留内部端口，已移除只验证自身的内存替身。尝试/回执的纯规则留在单元测试，不能证明持久化、事务隔离或恢复。现有 Python 底座报告也不能替代上游 Rust binding 的接入验收。

## zg 查询增强接入门

当前优先接入 [G2 查询图存储](G2_IMPLEMENTATION_PLAN.md)，独立 SDK 来源服务后置。上游已锁定 `3bf0d532ce928c02782c76d42cc289b1e49e8df4`；G2.0 已修复宿主测试，13 项 binding 与 5 项 Schema 探针通过；无软链独立源码包的上游 28 项及该原生库上的宿主复跑通过，见 [验收记录](G2_0_ACCEPTANCE_REPORT.md)。G2.1 已补齐真实候选事实适配、同次宿主 EntityId 绑定及完整结构往返，见 [G2.1 验收](G2_1_ACCEPTANCE_REPORT.md)；真实未知提交、联合发布和恢复核对仍待后续验证。图只引用宿主已有正文/向量和来源版本；宿主负责 generation、manifest、文件替换与资源协调。绑定最小门仍为参数化查询、类型化结果、显式只读/写事务、提交错误分类以及可复现的实际版本锁定。G0/G1 只检查候选事实，不要求提前完成通用 SDK 迁移矩阵。

连接应按操作独占；若上游事务不是 Send，不得跨 await/线程搬运，在同一个有界 blocking 调用中完成创建、查询、提交/回滚与释放。接入时验证旧读视图、新事务确认、未知提交隔离和重开，不在宿主添加 FFI。
