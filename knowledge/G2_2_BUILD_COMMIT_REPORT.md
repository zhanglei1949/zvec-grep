# G2.2 图内根与回执：首步实施记录

历史运行记录已迁入[归档索引](archive/pre-g4-validation/README.md)；文中的旧 reports 路径指归档内位置，机器记录链接的标题保留原始路径。

日期：2026-10-26。**只完成 G2.2 的图侧提交子集，不代表整个 G2.2 完成或图已发布。** 实施前已完成 [ANN 原生修复验收](ANN_READONLY_DIGEST_DRIFT.md)，后续验证使用同一固定版本补丁库。

## 已实施

- `GraphDbStore::create_build` 在新候选创建 GraphRoot、Receipt；普通事实候选的 Schema/指纹不变，打开时不加表、不隐式升级。
- `BuildSpec` 固定构建/操作 UUID、尝试、基准、配置及规则指纹；拒绝无效身份、不一致指纹、超出基准的来源修订及不匹配的代码/文档域。未知输入字段拒绝解码。
- 先检查已保存并完整读回的事实，再在一个短写事务中原子写入根和不可变成功回执。根绑定完整 `facts_digest`、全部目录修订和逻辑计数。
- 相同输入重试复用原成功证明及时间；改变 attempt 或基准返回冲突，不按完成顺序覆盖。
- 提交后以新显式 READ ONLY 事务实读根和回执；确认失败保留已知提交效果。没有提交后的取消检查将成功改为取消。
- `inspect_build` 只读核对，不修复或选择；缺失回执、未知格式不是成功证明。结果 `ConfirmedBuild` 不包含 selected/ready 承诺。

物理 Schema 中 attempt、修订、计数和时间使用已验证的 UINT64，覆盖宿主 u64 边界；不是静默转换为 i64。事实格式仍为 G2.1 版本；发布 Schema 有自己的组合指纹。配置只应包含图构建参数，不包含模型提供者凭据。

## 真实验证

三个新增用例使用实际 graphdb，覆盖根/回执提交与新只读确认、相同输入重试、变更尝试/基准冲突、只读重开、真实重复主键故障后的双表回滚、缺失回执拒绝、提交前取消、预算及输入/领域校验。

测试明确检查失败事务中根与第一条回执均已插入，再触发重复主键；回滚后两张表均无成功证明。该探针不替代提交响应丢失或进程终止测试。

最终 KG 原生 all-targets 回归 **59 通过、0 失败、0 忽略**，宿主真实双库往返用例 **1 通过**；三组件图 feature 的 Clippy `-D warnings` 和格式检查通过。命令和源码摘要见 [机器记录](archive/pre-g4-validation/README.md#g2-2-build-commit "包内：knowledge/reports/g2.2-build-commit/verification.json")。ANN 修复后的三组件全量 557/0/10 属于开始本子集之前的快照；本子集随后运行的上述检查分别记录，不合成为一次新的全量回归。
