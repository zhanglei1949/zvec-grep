# 通用知识图谱项目边界说明

当前开发主线以 [zg 查询增强 G0–G4](QUERY_ENHANCEMENT.md) 为准：代码关系和文档关系分别推进，不建立代码与文档关联；独立通用 KnowledgeBase SDK 完整重写后置。本文保留通用框架的长期范围，不作为当前 G0/G1 的全部交付承诺。

状态：范围基线，已纳入总体设计阶段确认的首版范围；不表示功能已经实现。

日期：2026 年 10 月 22 日。

z-knowledge-graph 是面向应用开发者的嵌入式知识构建、维护与检索框架，基于 graphdb 和 zvec，帮助应用把不同来源的信息组织为可追溯、可更新、可查询的知识。主要交付物调整为 Rust SDK，CLI 后续复用服务，后续按需求增加 MCP 接口和单机服务。原 Python Phase 1–3 已归档为迁移基线；当前 Rust 仅交付组件，尚未完成真实图存储接入，见 [重写安排](knowledge-delivery-plan.md#rust-重写前置阶段)。

graphdb 存储图数据与知识管理记录，zvec 存储向量和全文检索索引；本项目负责知识语义、来源管理、知识生命周期和面向应用的检索结果。首发场景覆盖本地文档知识、结构化知识与 Python/C++ 代码图，动态记忆作为后续领域套件扩展。

本文确定定位、用户、场景、功能与职责边界，不涉及具体知识模型、数据结构、检索算法、存储布局或任务与版本机制的内部设计。下文的功能是项目建设范围，当前底座能力单独说明。

公共知识模型、模块职责、生命周期、一致性与核心接口见配套的[总体设计与核心接口](knowledge-system-design.md)；验证顺序、首版里程碑及验收覆盖见[交付计划](knowledge-delivery-plan.md)。范围基线、总体设计和交付计划共同约束后续详细设计与实现，骨架跑通不等于首版完成。

## 项目定位

项目面向需要在应用中管理和使用知识的开发者。公共核心管理来源、独立支持、人工更正、有效知识与证据，文档和代码套件使用同一套维护与发布契约。应用可以导入已有结构化知识，也可以接入解析器或模型生成知识，并持续处理内容修订、人工更正和来源删除。查询结果应能回到依据，帮助调用方判断结果的适用范围和新鲜度。

“通用”体现在公共能力可以跨场景复用，同时允许领域规则不同：

| 公共能力 | 领域套件决定的内容 |
| --- | --- |
| 来源标识、身份、版本与新鲜度表达 | 什么对象和关系需要建模 |
| 导入、更新、更正、删除与重建流程 | 如何解析、抽取、消歧和处理冲突 |
| 精确查询、关系查询、检索与证据返回 | 如何选择、排序和解释领域知识 |
| SDK、能力接入、诊断与评测接口 | 文档、代码、记忆各自的生命周期规则 |

知识输入包括结构化记录、程序解析结果、模型抽取结果和人工维护内容。基础使用不依赖特定 LLM、模型服务或抽取提示词；使用模型时，抽取与 Embedding 由调用方分别配置能力提供者，支持本地部署与显式配置的远程服务。

项目价值通过知识是否易于维护、结果是否有依据、应用是否易于接入来评价。图结构用于支撑关系查询和证据组织，是否改善具体任务的效果及成本，需要在相同输入和任务条件下验证。

## 首发场景

首发围绕本地项目资料库展开：输入技术文档、Python/C++ 代码和已有结构化知识，查询实体、关系及相关证据，并在资料变化后继续维护知识库。

典型任务是：从技术资料与代码中查找某项设计或决策的相关对象、关联结论、实现符号与原文依据；文档修订、代码变更或来源删除后，能够判断原结果是否仍然有效。跨文档与代码的事实关联由显式链接、限定名或领域规则建立，语义相似只产生候选。

首发覆盖以下完整流程：

1. 创建本地知识库，接入结构化知识、基础文档和 Python/C++ 代码仓库。
2. 通过调用方提供的知识、解析结果或配置的抽取能力完成构建，记录来源。
3. 按对象、条件和关系查询知识，使用全文、向量或混合检索定位内容，再按预算扩展图关系，获取对应证据及来源位置。
4. 处理资料修订、重复导入、人工更正和来源删除，查看处理状态。
5. 关闭并重新打开知识库，继续查询和维护；按需导出和重建。

基础文档范围先覆盖纯文本与 Markdown。PDF、Office、图片、音视频及远程业务系统连接器后续按需求接入。结构化知识和调用方已完成的抽取结果应能独立导入。

文档与代码套件共同验证公共能力。代码图以 Tree-sitter 为 Python/C++ 默认语法解析器，Clang 为 C++ 可选语义增强。语法解析不等于完整的名称绑定和调用分析，未解析引用、候选目标与已确认关系分别表达。动态记忆需要时间、冲突和遗忘规则，后续单独设计。

### 首版功能范围

| 能力 | 对外提供的功能 | 边界 |
| --- | --- | --- |
| 知识库管理 | 创建、打开、关闭，查看配置、版本和状态 | 以本地单机使用为基线 |
| 数据接入 | 导入结构化知识、纯文本、Markdown 与 Python/C++ 代码，接收外部解析、抽取结果和预计算向量 | 保留来源标识、版本及参与构建的文本快照，不默认覆盖任意格式 |
| 知识构建 | 文档分段与可配置的实体关系抽取；代码语法解析、符号解析与关系构建；Embedding 与索引构建 | 模型由调用方配置；无模型时仍可使用结构化操作和基础代码解析，不承诺完整调用图 |
| 知识维护 | 新增、修订、重复提交处理、按来源删除和重建，说明未变化、局部处理或完整重建的原因 | 重复提交不应产生重复知识；删除来源需处理受影响的派生结果，并保留仍有其他来源支持的内容 |
| 人工更正与实体对齐 | 以独立记录更正知识、确认或撤销实体对齐，标明人工维护内容 | 确定性身份可自动合并，同名或语义相似只产生候选；重建保留更正，失效目标标记待复核 |
| 查询与检索 | 精确、全文、向量和混合检索，有界图扩展、关系及路径查询，返回相关证据 | 全文与向量为首版验收能力；使用向量检索需配置 Embedding 或提供向量，缺失能力默认报错，显式允许后才降级 |
| 来源追溯与知识检查 | 从结果回到原文或原始记录，检查声明的限定条件、支持、更正、争议与选择依据 | 区分原始记录、自动抽取、推断与人工确认内容 |
| 构建状态 | 查看处理进度和失败原因，提供重试、取消及重开后的恢复入口 | 区分任务状态、图提交、索引写入与各查询路径就绪；取消请求不等于立即停止底层调用 |
| 导入导出与诊断 | 导入导出知识及必要证据信息，检查、修复、重建索引、检查检索执行过程与显式清理旧产物 | 逻辑导出与数据库快照分别表达，说明是否包含本地文本快照；不包含模型服务、密钥或任意外部文件 |

目标首版通过 Rust SDK 和后续 CLI 提供上述能力。知识检索与答案生成分别开放：调用方可以只取证据，自行组织上下文或生成答案。问答示例可以验证接入流程，答案生成策略由应用或可选能力提供者决定。

### 结果与维护约定

- 查询结果能够关联到来源，表达来源版本、新鲜度及必要的执行状态。图中存在一条关系，不代表其内容已经被验证为事实。
- 相似度、关系路径和证据依据分别表达，调用方能够辨别结果由何种方式得到。
- 完整结果、近似召回、预算截断、取消和失败需要区分。查询失败不能被包装为没有相关知识。
- 接收成功或写入提交成功，不直接等于全部构建完成。项目在确认相应查询路径就绪后报告可查询状态。
- 来源保留、更正、删除和重建的影响范围应清楚可查。证据位置与来源支持分别管理，人工维护内容与可重建结果分别确定保留规则。未裁决的互斥声明保留争议状态，不按摄入顺序静默覆盖。
- 语义失效的描述、摘要、推断和检索投影不能继续进入新发布的结果。显式降级可以减少检索通道，不能让无效知识重新生效。
- 候选版本未就绪时继续使用上一版；检索不得暴露构建中间产物。跨库部分成功由任务核对、幂等重试和修复处理，不宣称跨库原子事务。
- 来源更新、更正或删除形成明确的发布影响集合。其支持变化及跨来源依赖失效在同一图侧发布视图中生效；失效派生产物不能等待所属来源另行发布后才退出。
- 来源范围用于裁剪知识、支持和证据，不重新裁决全库已存在的争议或撤销有效人工更正。相关人工效果随命中目标说明，不借此扩展到无关来源。
- 一次查询使用一个已发布的 Embedding 空间；全库更换空间需完成声明覆盖范围后统一切换。缺少请求范围内的向量覆盖应明确报错或显式降级，不能冒充完整查询。
- 默认保留参与构建的本地文本快照及必要版本追溯；首版不提供任意历史全库查询或回滚。旧产物清理受有效引用和读取者生命周期约束。

这些是对外行为要求，对应模型与接口约定见配套总体设计，物理结构与完整实现参数留到详细设计。

## 运行与交付边界

默认使用方式是应用进程内嵌入 SDK。首版支持本地、单机、单一信任域，知识库与来源范围用于组织和限定访问，不据此宣称具备多租户安全隔离。

首版在单一信任域内仍承担基本数据保护：摄入内容视为不可信，敏感文件按默认与配置规则在快照捕获前排除、不计入覆盖；发往远程提供者的内容按声明范围过滤并留审计记录，密钥与凭据不进入发送内容、指纹、日志或诊断。快照、graphdb 与 zvec 数据的静态加密不由 SDK 内置，首版由调用方在文件系统或卷层负责。具体机制见[总体设计](knowledge-system-design.md)的输入数据处理与安全边界一节。

首版支持全本地运行：模型权重、运行依赖和所需解析资源准备完成，且本地提供者具备所需能力后，文档抽取、Embedding、知识维护及全文/向量/混合检索可在断网环境中完成。基础结构化知识操作、文档结构与全文索引、代码语法解析不要求模型密钥或联网；向量能力仍需本地 Embedding 提供者或兼容的预计算向量。

模型权重、推理运行时及模型服务的部署与生命周期由调用方管理，SDK 不在运行中自动下载权重或启动、停止外部模型服务。全本地配置使用本地权重执行，不隐式调用或回退到云端；远程调用须显式配置服务、允许发送的内容范围和适用预算。本地模型服务可独立于嵌入式知识库进程运行。具体模型型号与服务软件作为接入示例和评测配置，不成为架构的必选依赖。

本地与远程模型输出均作为候选知识，经过类型、证据、支持与发布校验。格式合规不代表知识正确，抽取质量需要按固定语料评测；本地部署免去云端按次调用费用，计算资源与模型许可仍由部署方确认。

构建任务依赖宿主进程运行。关闭嵌入式应用后不承诺任务继续执行；首版在重开后核对未完成任务，区分可恢复、需重试和提交结果待确认的情况，不无条件重放模型调用。CLI 不以进程退出后的后台线程承诺持续运行。

查询、构建和模型调用分别暴露适用的资源及费用限制，包括时间、访问量、输出量和模型调用预算。上层预算需要与 graphdb 的资源控制衔接，不能把逻辑额度直接当作进程内存硬限制。

知识库统一限制排队任务、并行准备、批次缓冲和暂存空间。空间不足或旧版本因读取者占用不能回收时，对新构建施加背压或拒绝接收；不能清除仍被读取的产物来满足额度。知识库打开时核对库身份、存储世代与格式兼容性，不兼容迁移通过显式新库流程完成，保留稳定业务 ID、支持和人工记录。

后续服务模式统一持有数据库实例。当前 graphdb 同一目录跨进程允许一个可写实例，或多个只读实例，二者不同时打开；服务、CLI 与其他客户端的接入方式需要遵守这一约束。

## 非目标

| 非目标 | 边界说明 |
| --- | --- |
| 分布式数据库与集群平台 | 首版不覆盖分片、多机事务、高可用集群或跨地域复制 |
| 完整 Agent Runtime | 任务规划、工具选择、会话管理和用户确认由宿主负责 |
| 完整知识管理产品界面 | 首版交付 SDK 与 CLI，交互产品由宿主应用构建 |
| 任意格式与领域的自动建图 | 逐步接入格式和领域套件，不承诺任意输入均可正确抽取 |
| 自动判定事实真实性 | 提供来源、状态和更正能力，领域判断由规则、人工或应用策略完成 |
| 统一所有场景的本体与治理规则 | 共用公共契约，文档、代码和记忆保留各自规则 |
| 完整语义网标准与推理平台 | RDF、SPARQL、OWL、SHACL 等互操作及推理能力按具体需求评估 |
| 多图数据库兼容框架 | graphdb 是首个正式图存储底座，首版不承担多个图后端的等价兼容 |
| 跨独立存储的原子事务 | graphdb、zvec 与原文快照分别持久化，上层管理版本、就绪、发布和修复，不承诺跨库原子提交 |
| 任意历史查询与全库回滚 | 首版保留当前可用版本及必要追溯，不将数据库 MVCC 快照当作业务历史服务 |
| 全量流式处理与无限规模 | 受当前底座及配置资源约束，支持范围经验证后声明 |
| 本地静态数据加密 | 快照、图与索引的 at-rest 加密首版不内置，由调用方在文件系统或卷层负责 |

## 与 graphdb、zvec 的职责划分

### 分层职责

| 归属 | 负责内容 |
| --- | --- |
| graphdb | 通用属性图、Schema 与约束能力、Cypher 和计划执行、批量读写、事务可见性、持久化、恢复及底层资源控制；保存知识、来源、证据关联、更正和任务发布记录 |
| zvec | 向量与全文索引、候选召回及其存储恢复；保存可重建检索投影，不决定知识有效性或发布状态 |
| 通用知识项目 | 来源与本地文本快照管理、知识维护流程、公共元数据契约、构建发布与修复、检索编排、证据封装、SDK 与 CLI |
| 领域套件 | 领域模型、解析与抽取规则、身份生成与实体对齐策略、冲突处理及领域查询工具 |
| 外部能力提供者 | 模型推理、Embedding、专用解析和外部检索；Tree-sitter 提供默认语法解析，Clang 提供可选语义增强 |
| 宿主应用 | 用户交互、身份上下文、Agent 编排、工具选择及人工确认 |
| 可选服务或 MCP Adapter | 协议接入、请求校验，以及服务模式所需的身份映射、授权、限流和审计 |

### 跨层需求的归属原则

需要领域知识才能作出的决定由上层负责；需要数据库统一执行和恢复的保证由 graphdb 负责。上层使用公开接口，避免复制事务、WAL、恢复和内部版本管理机制。

zvec 通过独立适配层接入；Rust 复用宿主 workspace 的公开 Rust 绑定，Python API 仅用于冻结基线。知识项目管理图与检索投影之间的业务 ID、来源版本、构建指纹和发布关系，不进入任一底座内部实现跨库事务。首版 SDK 通过受控接口查询图，不开放绕过维护规则的直接数据库写入。

| 需求 | 知识项目及领域套件 | graphdb |
| --- | --- | --- |
| 按来源修订或替换 | 决定哪些知识受影响，以及哪些人工或共享内容应保留 | 提供可靠的查询与批量写入；必要时建设通用原子操作能力 |
| 稳定身份与重复提交 | 定义业务身份、重新抽取后的沿用规则及幂等含义 | 提供主键、约束、定位与事务执行能力 |
| 更正和冲突 | 判断新旧内容是补充、替代还是矛盾 | 按明确条件执行更新，并处理可见性与恢复 |
| 知识新鲜度 | 记录来源及抽取信息，决定何时对外报告就绪 | 提供明确的读写可见性契约，支持上层核验 |
| 派生结果更新 | 调度抽取、Embedding、摘要或其他构建任务 | 对纳入本库事务边界的数据提供提交、读取和恢复保证 |
| 删除与重建 | 决定依赖影响、保留策略和重建范围 | 执行相应的数据操作，保证数据库一致性 |
| 查询预算与证据输出 | 组织检索流程，限制输出和模型上下文 | 限制实际执行资源，并返回可识别的错误与状态 |

### 当前底座约束

原设计核对的本地版本为 graphdb `9d6e966ef0ae214cff8d5018efe1dafb37bc2a99`、zvec `a4347e31f1b8e216cffba59285427a3b78551229`；以下为该版本的设计约束，不能据此声明 Rust binding 或当前宿主原生库的行为。graphdb 已有 Python API、属性图与 Cypher、事务持久化、图查询及只读原生扩展入口。

- 该 graphdb 版本没有向量或全文检索实现，本项目由 zvec 承担这两类检索，不等待 graphdb 内置能力。
- 当前 Schema 不支持 ALTER 或 DROP，写入不支持 MERGE。知识项目的更新、迁移与重复提交行为需要据此设计。
- 查询结果全部物化，尚无 spill。上层分页或分批返回不能被视为底层流式执行。
- TP 提交返回不能替代发布可见性确认；需要用新的显式只读事务，按实际业务读取路径核验。
- 数据库 MVCC 快照不能直接替代知识历史；需要保留的来源历史与人工更正由上层明确管理。

这些约束以所核对版本为准，升级或更换绑定后重新确认。zvec 的批量写入需检查逐项结果，并验证所选全文与向量接口。Python Phase 1–3 的组合证据见 [历史验收](archive/python-evidence/phase3/PHASE3_REPORT.md)；Rust 目前只验证组件和 zvec 投影，真实图侧发布仍待接入。参考项目的能力不能直接当作本项目已有保证。

## 项目组织边界与首版验收

本项目已迁入 zvec-grep，Rust 实现在 `rust/crates/zg-knowledge/`，设计记录保留在 `knowledge/`，Python 基线位于 `knowledge/archive/python-baseline.zip`；不将领域逻辑并入数据库内核。Rust 复用宿主 zvec 与后续代码解析能力，graphdb binding 由上游维护。Python 活动源码和六项旧依赖登记已退役；归档保留原始提交与恢复资料，宿主 Rust 的 zvec 和 Tree-sitter 依赖继续使用。维护来源、版本、许可证、构建方式和组合验证记录。

知识项目在宿主仓库内维护公共能力、文档套件、代码套件和工具入口。抽取规则由本项目维护，与 parser、grammar 和符号解析配置一起参与构建指纹。模块职责见总体设计；Rust 真实图存储接入及后续领域 Schema 仍按交付门验证，不由组件测试推定完成。

首版至少用一套固定资料与查询完成以下验收：

- 从结构化知识、基础文档和 Python/C++ 代码构建知识库，经关闭和重开后仍可查询。
- 精确、全文、向量、混合检索与图扩展可用，分别核对召回、关系和证据质量。
- 查询得到相关知识与关系，并能回到对应来源及位置。
- 重复导入不产生非预期重复；修订、删除和重建后的结果符合声明的维护规则。
- 人工更正能被识别和保留，重新抽取不会无声覆盖。
- 语法错误、宏、重载和动态调用不会被静默包装为完整代码语义；未解析项和符号变化影响明确。
- 图或索引部分失败、进程中断和提交结果不确定后可核对恢复；并发查询不暴露中间产物，竞争发布不覆盖较新结果。
- parser、grammar、抽取规则、模型版本、提示模板或输出契约变化后，可解释重建范围与结果变化；仅更换 Embedding 时复用仍适用的解析和知识产物。
- 预先准备资源后，以真实本地抽取与 Embedding 组合完成断网构建、增量维护、检索与关闭重开；模型故障不发布中间产物或隐式转向云端。
- 对固定标注语料分别核对抽取准确性、否定与限定条件保留、证据定位和输出格式，不用格式通过率替代知识质量。
- 处理中、就绪、失败、取消和资源超限的状态明确，调用方能够判断是否可继续使用结果。
- 跨来源依赖失效、范围内证据、全库向量空间切换、更正链与传递对齐的撤销均有固定预期用例。
- 混用存储目录或格式不兼容时明确拒绝打开；迁移、导出与重建保留必要身份、支持、人工效果及证据，不误删仍被读取的旧版本。
- 敏感文件在快照前排除且不计覆盖；远程发送按声明范围过滤并可审计，密钥不进入日志、指纹或诊断。
- 对预先选定的关系与证据任务，分别评价知识质量、维护正确性、资源成本和接入成本，不从外部基准推导本项目收益。

底座 Spike 在正式试验前记录目标环境、代表性知识负载及资源/延迟判定阈值，试验数据不满足约束时先修订设计。首版完成以交付计划中全部首版里程碑和总体设计验收项为准；LlamaIndex 等生态适配单独作为后续可选交付。
