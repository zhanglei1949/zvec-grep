# Go／Java／C／C++ 真实查询效果评测计划

R0—R5 已完成。本文保留题集、执行顺序和验收协议，当前结果及残留见 [S2 验收矩阵](S2_ACCEPTANCE_MATRIX.md)。冻结 v1 与配置修订 v2 并存，来源包与摘要见 [评测 fixtures](../benchmarks/zg-retrieval/fixtures/g4-compiled/README.md)。模型、默认预算与输出契约不变，构建成本继续暂缓。

## 目标与边界

回答三个问题：普通检索能否找到回答问题的源码，Augment 是否补充了必需证据，Constrain 是否在正确范围内返回足够正文。分别报告来源就绪、关系解析、文件命中、可见证据覆盖和明确退化，不以功能夹具通过代替真实查询效果。

- 构建耗时、RSS、磁盘成本优化继续暂缓，不重跑三轮／六场景成本对照，不调整六项未通过门禁。索引是评测准备，保留准备日志即可。
- 普通排序、配额、模型、默认查询预算和超预算退化行为保持现状，不新增部分结果机制或查询入口。
- 只评估现有静态支持范围及其边界。JS／TS、文档语义抽取、跨语言调用推断、构建系统执行和新存储抽象后置。
- 真实源码采用固定提交中的原样组件子集；本轮结果只适用于这些子集，不代表全仓或全语言召回率。

## 题集与语料

### 固定四个来源

沿用 M4／M6 的仓库与提交，扩展其过小的代表用例。R1 根据源码确定文件清单和依赖，不根据 zg 的输出选择文件。

| 语言 | 仓库与固定提交 | 出题范围及典型问题方向 | 必须保留的边界 |
| --- | --- | --- | --- |
| Go | google/uuid，`0f11ee6918f41a04c201eceeadf612a377bc7fbc` | 以 uuid.go、util.go、hash.go、marshal.go 及必要同包来源为起点；解析、校验、编码与哈希生成。例如“解析失败怎样传递到会 panic 的入口？” | 同包／静态调用可证明才连边；未知接收者、外部接口实现不推断；构建条件来源另列 |
| Java | Kuzu，`89f0263cc7a1fd9c396d2c4953747a013556a7f9` | Java API 的 Value、DataType、相关具名类型和对应测试；空值创建、生命周期检查、静态入口及声明关系。例如“创建空值的入口和验证这一行为的测试在哪里？” | 实例 close、JNI/native、外部 classpath 不补造目标；extends／implements 仅标注明示且可证明的关系 |
| C | Nanoarrow，`a579fbf5d192e85b6249935e117de7d02a6dc4e9` | common/utils.c、schema.c、array_stream.c 及所需头文件；分配／释放、错误处理、Schema／流初始化。例如“默认分配器释放内存时经过哪些函数？” | 编译单元隔离；原型与定义分开；宏、函数指针及外部 free 不猜测 |
| C++ | graphdb，`c1a77be7d3327fdd72b1be23be8b2aac1dc2f8ae` | common/string_literal.cc、error.cc 及相关声明／直接依赖；转义解码、Unicode 检查、异常与命名空间关系。例如“Unicode 转义在何处校验并转成 UTF-8？” | std::stoul、模板、重载和未知接收者不猜测；compiler/literals.cc 的已知 grammar 失败单列 |

上表是源码审阅的起点，不是已验证的可建图文件清单。R1 必须输出精确原路径、包含／排除理由、依赖闭包内已收录与未收录来源、配置和摘要。头文件或外部依赖未收录时保留真实 include/import 与未知目标，不删语句、不补假定义。Java 测试与生产代码分开标注；C／C++ 用真实原路径保留编译单元关系，不能简单拍平文件。

若一个组件不足以形成独立问题，R1 在同一固定提交内补充相邻组件并说明理由；不得用同一问题换一种说法凑数。全部语料和题目冻结后再运行产品。冻结后发现未就绪、语法限制或漏标，不删题或重分正常／负向角色；修订另建输入版本，两个版本结果分别保留。

### 48 道自然语言主问题

每语言 12 道，共 48 道；每题均做 Off／Augment 配对，其中固定 8 道同时做 Off／Constrain 配对。沿用上一轮英文主问句，报告以中文解释；本轮不叠加中英双语维度。

| 类别 | 每语言题数 | 证据要求 | Constrain 子集 |
| --- | ---: | --- | ---: |
| 行为／错误条件定位 | 3 | 实现中的关键分支与返回／错误处理，不能只靠注释 | 0 |
| 直接调用／调用者 | 3 | 调用位置与目标实现；关系是否可静态证明另行标注 | 3 |
| 跨文件依赖／职责分工 | 2 | import/include 或使用位置，以及相关源码实现／声明 | 1 |
| 多步处理链 | 2 | 至少两个不同处理步骤的正文；是否存在可遍历路径由源码独立确认 | 2 |
| 类型／范围内职责 | 2 | Java／C++ 优先显式类型关系；Go／C 使用类型声明、字段和函数职责，不制造继承／实现关系 | 2 |
| 合计 | 12 | 每语言至少 6 题需要两个以上独立证据区间，其中至少 4 题跨文件 | 8 |

每语言至少 8 道以行为或维护意图描述问题，不写答案函数名、答案路径或行号；其余最多 4 道可包含用户通常已知的公开 API 名，不直接给答案文件。题目不能只是 Locate 请求改写。Constrain 的锚点属于用户显式提供的范围条件，单独冻结，不作为 Augment 的额外种子；三种模式使用同一主问句。

Constrain 的必需证据与文件真值限定在其冻结范围内，Off／Constrain 按同一范围内真值比较；不把有意排除的范围外证据计作缺失。范围真值来自源码与已声明关系，不从候选返回的 scope 反推。范围构建不完整时明确失败，不能返回貌似完整的空结果。

### 标注与边界用例

每道题保存：题目与摘要、仓库提交、来源字节摘要、角色、必需证据的路径／UTF-8 起止字节／原文、相关文件与等级、适用的调用位置／目标／关系、Constrain 锚点与预期范围，以及已知未知项。实现、调用位置和声明各有其作用，不以整个长文件或整段函数代替最小充分证据。

标注生成脚本只读取固定源码和独立声明；不得调用 zg 或消费产品响应。位置使用独立源码／AST 核对，不能复用被测解析结果作真值。自然语言题不因当前解析器暂不支持某条真实关系而删除：正文真值与图的解析承诺分别记录。没有人工复核就明确标注未人工复核；未标注新增内容保持未知。

另设 8 组边界验收，不计入 48 道效果题的收益均值，具体来源和请求在 R1 冻结：

| 语言 | 两组边界 |
| --- | --- |
| Go | 真实未知接收者调用不误连；带构建条件而缺少构建上下文的来源显式 incomplete／not_ready |
| Java | 真实实例调用不猜接收者；native／外部实现不伪造源码目标 |
| C | 外部 free 不连到同名本地函数；真实函数指针或宏调用不冒充静态直接调用 |
| C++ | std::stoul 等外部调用保持未知；原 compiler/literals.cc 默认参数 grammar 失败保留明确 not_ready |

建图未就绪的边界用例使用独立工作区，避免污染主评测题集；它们与主语料的角色在首次运行前确定。现有目标失效、歧义、配置漂移、过期引用和五道预算负向继续复用既有回归，不为凑题数再造一套。不得静默改用更宽预算、缩小查询范围或删减调用。

## 实施顺序与阶段验收

### R0：交接可复现的查询基线

以已验收查询修复之后的固定源码和制品作为基线，不以当前混合工作区替代。固定源码补丁、二进制／包、原生库、模型、运行参数与环境摘要；分别使用独立的源码、构建、索引和结果目录。

另一任务的 `relations/{bound,code,markdown}.rs` 等后续变更原样保留并单列，不默认并入本轮基线。后续若需合入，作为有独立身份的候选评估。解包载荷启动 SIGKILL 的已知限制继续记录；允许沿用与包载荷逐字节相同的固定原构建路径，不将其视为安装验收。

现有矩阵新记录的只读查询改写 proxima 文件与并发图读取超时须作为已知正确性问题登记，不能算作构建成本而略过。复用索引／向量查询前后清单核验；发生摘要变化的运行不作为干净的因果对照，也不据此取消不变断言。可以继续其余语料和离线标注，受影响项单列待处理，不直接把全部失败归因于已知问题。

**验收：**基线可独立还原，运行路径与制品字节一致；来源／模型／配置与索引身份可核对，其他任务的修改未混入；所有已知阻塞均有具体记录。未解决的存储完整性失败不能被标记为通过。

### R1：一次冻结四语言输入与独立标注

按 Go → Java → C → C++ 审阅固定提交，完成组件来源清单、48 题、32 个 Constrain 配对和 8 组边界角色。记录 Go go.mod、Java package／根映射、C／C++ 显式语言根与适用的 compile_commands 字段；配置仅用于静态解释，不执行 compiler command。评测生成配置须单列出处与摘要，不冒充上游已有配置；无法确定的构建上下文保留未知。

新建独立协议 `g4-compiled-v1`、输入 `data/g4-compiled-v1.json` 和仅依赖源码的标注脚本，评分复用 `visible-bytes-v2`。输入身份、标注脚本、文件选择、查询文本、角色、范围及调用矩阵分别冻结。v7／v8／v9 和原 Rust/Python v2 输入不改写。

**验收：**每语言分类与跨文件配额满足上表；全部必需区间可在固定字节中回读，调用／关系与正文真值分开；48 题、32 个范围和 8 组边界无重号、漏标或冻结后改角色；冻结发生在首次产品运行之前。

### R2：复用现有 runner 接入四语言

复用 `core/g4.mjs`、`g4-run.mjs`、`g4-parse.mjs`、`g4-report.mjs` 的配对、公开响应校验和评分。仅补独立协议所需的任务数量分支、来源清单、大小写扩展名及模块／配置输入；现有来源留档中的 Rust/Python 扩展名硬编码也要替换为该输入的精确清单。保持旧协议断言与旧报告重放，不另建通用评测框架。

正式效果统一走现有 MCP 公开响应。48 个 Off／Augment 配对和 32 个 Off／Constrain 配对各重复 5 次，第 5 次评分，共 **800 次检索调用／制品**；两类配对中的 Off 分别执行，不去掉重复调用。配对顺序交替；准备、重开、8 组边界及诊断调用另列，不混入该计数。评测脚本、标注、日志和模型缓存不能落入被索引范围。

| 固定项 | 沿用值 |
| --- | --- |
| 模型／设备／检索 | local/potion-code-16m-v2／CPU／hybrid |
| 普通请求 | limit=10，preferSymbol=false，autoUpdate=false，freshness=eventual；默认预览 |
| Augment | seeds=5，最多 2 跳；各题关系、方向及范围参数在 R1 冻结 |
| 超时 | 请求 30 秒，图查询 5 秒 |
| 图预算 | nodes=2000，edges=10000，candidates=5000，mapping_units=5000，output_bytes=65536，filter_bytes=262144 |
| 索引策略 | 每仓库／每制品独立新建；同一制品的配对共用其已冻结索引；默认预算不随语言变化 |

**验收：**离线评分测试覆盖四语言路径、`.C/.c`、`.H/.h`、Unicode、LF／CRLF、空行、省略与截断；v9 已有响应重算不变。完整调用矩阵可在准备失败时列明阻塞项，不能用少跑调用换取通过。8 组边界复用四入口核对，预期状态、目标和证据一致。

### R3：按语言执行基线并逐题归因

执行顺序为 **Go → Java → C → C++**：先核对包／静态调用，再核对 Java 类型与实例边界，然后 C 编译单元，最后 C++ 命名空间／grammar 限制。四语言输入已经一起冻结，前一语言的结果不用于修改后一语言题目。

每语言保留每次原始公开响应，分别输出 Off／Augment 和 Off／Constrain 的普通文件排名、必需区间覆盖、有效补充、退化及范围检查。所有缺失区间按“源码事实与解析 → 普通命中及种子 → 遍历 → TextMap／来源版本 → 公开可见正文”定位。预算问题记录触发维度、阶段和已用资源，诊断复用现有公开操作与内部测试，不新增产品诊断接口。

**验收：**800 次计划调用逐项有记录；未就绪、超时和错误独立列出，不从分母中静默移除。每个缺失区间有可核验原因或明确待诊断状态。图不存在可证明路径、种子未选中、短预览未展示和实际超预算分别报告，不统称漏召回。合法退化不自动认定为产品缺陷。

### R4：有依据的最小修复与复测

只修复 R3 已复现、属于当前声明支持范围的抽取／解析、种子／映射、证据展示或重复读取／错误计费缺陷。优先复用既有实现，每项修复有最小复现、回归和对应缺失证据的变化记录。规则变化更新指纹并重建图；不能查询旧 ready 产物。

有产品修改时，基线与最终候选均在同一冻结输入、评分与环境下完成 800 次对照；逐语言、逐题比较改善、持平、回退与退化。基线完整且身份未漂移时可复用 R3 结果。没有确证缺陷则不为制造收益改代码，直接交付基线和诊断，不重复运行相同制品充当候选。

**验收：**不能仅靠评分变更、缩短标注或扩大预算宣称改善；已修复项必须补回相应证据或消除错误退化。候选不引入普通排序／配额漂移、越界、无效证据或新的未处置退化；其他证据回退逐项解释并修复，不能由平均收益抵消。确实超出现有支持范围的项保留缺口，另立后续计划。

### R5：兼容回归与交付

复跑现有六语言／公共模型夹具和 Rust/Python v9 效果回归，确认来源、更正／退出、图读取及原有查询收益未被破坏。依据实际修改运行受影响的评测框架、KG、engine、CLI／MCP／daemon 检查、格式与严格 Clippy；只改评测代码时不重跑整套无关原生测试。现有存储摘要失败不得以过滤掉测试的方式转为通过。

交付新报告与独立证据归档：输入／来源／制品摘要、精确复现命令、800 次调用矩阵、8 组边界四入口结果、逐题排名与覆盖、全部缺失区间、修复证据、全部失败与阻塞。旧实验及归档保持原样，更新主计划、索引和 S2 矩阵的当前状态。

**验收：**他人可从固定源码与输入重算报告；每语言分别给出“评测完整性／功能正确性／证据质量／残留问题”结论。评测交付完成不等于所有查询有效或获得正收益，有失败就保留对应未通过项。

## 统一评分与完成标准

1. **完整性：**版本、语料、模型、配置及调用数一致。缺失调用、制品漂移、无法复核的来源字节阻止对应对照验收；保留失败尝试，不能记作成功样本。
2. **查询正确性：**每个 Off／Augment 配对的普通项、顺序、配额一致；Constrain 正文与元数据零范围泄漏，范围不完整明确失败；目标与位置真实，无猜测关系、失配证据或错误空结果。
3. **证据质量：**沿用 v9 的可见字节规则，分别报告必需区间完整覆盖均值、必需字节覆盖、全部必需区间均完整的题数，以及相对 Off 的有效新增证据。文件 Hit／MRR／nDCG 作为辅助。指针、文件名或未经展示的原始范围不算已收到正文；未标注内容保持未知。
4. **失败与预算：**报告全量计划题数、可执行题数、未就绪／错误／超时／退化分布和实际质量分母；不能只展示成功子集均值。真实超预算沿用原退化，默认预算不变。边界用例与正常效果题分别汇总。
5. **对照限制：**新四语言不与 Rust/Python 分数直接作产品前后提升对比；有修改时只比较相同新输入下的基线与候选。逐语言报告为主，整体平均为辅；不外推全图召回率、全仓支持或回答正确率。
6. **成本边界：**查询耗时 P50／P95、公开输出字节及实际预算消耗继续观测，不设置新的构建时间／RSS／磁盘验收门槛。六项构建成本门禁仍未通过且优化暂缓；安装路径 SIGKILL、只读存储摘要问题和剩余原生故障窗口继续单列。

本轮不设人为正收益门槛。若只完成四语言基线和诊断，应明确写“尚无新产品召回改善”；若部分语言未就绪或正确性仍失败，报告相应失败，不将整轮标记为四语言能力全部通过。
