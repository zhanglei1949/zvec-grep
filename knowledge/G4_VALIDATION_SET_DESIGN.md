# G4 执行计划：代码图正确性与检索效果验证

日期：2026-10-29。状态：执行完毕，整体验证未全部通过。本文是 G4 的唯一执行规格；结果见 [G4 验证报告](G4_VALIDATION_REPORT.md)，原始记录见[证据归档](archive/g4-validation/README.md)。

## 1. 目标与边界

基于 G3.0～G3.3 已交付的 Rust／Python 静态关系，验证整仓 explore、Augment 的证据补充收益、Constrain 的范围准确性及代价。先做 L0～L2，不接回答 Agent。

首批外部语料为 ripgrep 与 requests；zg 自身只作开发验证。八语言、文档图、语义／记忆模型、接口调整、Debug 超时优化和 L3 后置。不修改语雀，不做性能重构，不改变 ready、完整性检查、预算、产品 API、协议或物理 Schema。

## 3. 基线与整仓 explore

- 固定 HEAD、dirty/untracked 源码、原生依赖、Release 文件和模型／分词器摘要，保留其他工作。
- 复用 G3 与 P3 已有验证，只补跑受改动影响的检查。P3 Release 默认预算通过，Debug 仍超时，二者分开记录。
- 使用 P2 已冻结发布视图，先核对来源与存储摘要，不宣称当前工作树全仓覆盖。
- 14 个请求覆盖 locate、callers、callees、neighbors、expand、path、references，各两例；覆盖唯一／多义、重复调用、自递归、跨文件、两跳、无路径及未解析引用。
- 预期来自冻结源码；可独立确认的部分才计分，语料缺少的工况明确记录，不能修改语料补造样本。
- 各请求独立 Release 进程运行三次，比较剔除耗时后的结果、完成状态及证据。前后核对文本／向量／图和发布状态，explore 不加载模型、不刷新、不写入。
- 代表请求复核 Rust／CLI／MCP／daemon 一致性，其余复用既有契约回归。

## 4. 外部语料与标签

| 语料 | 固定方式 |
| --- | --- |
| BurntSushi/ripgrep | 首次准备解析远端默认分支并记录完整 commit，此后不变 |
| psf/requests | 复用 `46e939b5525d9c72b677340985582b04b128478a` |

仓库根为工作区。首次冻结时记录原生忽略规则、文件大小限制、Rust／Python 选择、模块配置、实际选中和排除清单；在查看效果前完成构建、发布、关闭重开与 ready 检查。问题、标签和报告放在 checkout 外。

每仓 24 道关系题，共 48 道，覆盖定位、入／出向调用、包含／导入、扩展／路径和引用诊断。每仓预选 12 道配套自然语言题做 Off／Augment，其中 8 道配明确锚点和范围做 Off／Constrain。原 `requests:16` 与标签不改，单列结果。

标签分开保存：

1. 源码事实：实体、引用位置、真实目标、路径及必需 UTF-8 证据区间。
2. 契约预期：应解析、多义或因动态／不支持而弃答；不能把未实现的真实关系改标为不存在。

以源码和独立工具核对，在被测查询前冻结；未确认题保留 pending，不计正式质量分。每条标签保存来源摘要、原文和标注依据。未穷举的关系与证据标为未知，不默认判为无关。

## 5. 评测框架与固定协议

复用 `benchmarks/zg-retrieval` 的 runner、公共工具和评分层，不新建 benchmark／CI。显式 v7 配置与数据独立版本化；v6 配置、20 题、标签和运行入口保持原样。产品公开接口不变。

runner 使用带 graphdb feature 的 Release 候选包，通过公开 MCP index／explore／search 采集；普通结果、图补充、范围、证据和完成状态分别解析，不用隐藏 structuredContent 给正文加分。保留原始请求／响应、错误及摘要，支持离线重算。

| 项目 | 固定值 |
| --- | --- |
| 模型／设备 | `local/potion-code-16m-v2`，CPU |
| 检索 | hybrid、limit=10、preferSymbol=false、autoUpdate=false、freshness=eventual |
| 图 | Augment 5 种子、最多 2 跳；关系和方向逐题冻结 |
| 期限／预算 | 请求 30 秒、图阶段 5 秒，沿用现有默认资源上限 |
| 视图 | 每仓每次实验新建索引，配对请求共用同一发布视图 |
| 顺序／重复 | 每臂每题 5 次，逐题交替先后；第 5 次质量，全部记录耗时与错误 |
| 耗时 | 调用方总耗时，包含打开与资格核验；阶段字段只作辅助 |
| 输出 | 不二次裁剪；记录公开 UTF-8 字节数 |
| 构建成本 | 文本构建与图附加构建分别计时，记录峰值 RSS、磁盘增量；不计查询延迟 |

Off／Augment 普通结果及组的成员、顺序和配额必须一致，图补充单列。Constrain 按独立范围任务评分，不要求与 Off 结果相同。串行查询期间不编译或运行重负载。

## 6. 指标、验证与交付

| 层面 | 指标 |
| --- | --- |
| L0／explore | 定位、关系正确率与覆盖率、路径、逐引用位置、弃答与完成状态 |
| Augment | 必需证据覆盖增量、有效新增证据、错误关系、无关／未知补充、降级率 |
| Constrain | 范围内证据覆盖、越界内容、空范围／无匹配区分、失败率 |
| 排序 | 适用题的 File Hit／MRR／nDCG；原生排名，图不拼入普通排名 |
| 成本 | 配对耗时、输出、错误／超时、构建时间、RSS、磁盘 |

正文证据须与冻结摘要、区间及实际字节一致。文件名、范围或关系声明不算正文证据。小样本延迟只描述该协议下的观察，不宣称 SLA 或广泛收益。

新增框架测试：版本选择、调用矩阵、公开图响应、证据计分、失败／截断、离线重算、旧 v6 回归。只有产品代码实际修改才补相应产品回归。

未 ready、重开失败、缺调用、版本／摘要变化、未完成伪空、Augment 改普通结果或 Constrain 越界时，不得给出全部通过结论。发现缺陷保留失败，修复另列变更和候选身份，不静默覆盖旧运行。

交付：冻结输入、公开调用、可重算评分、机器报告、简练中文结论和遗留项。完成不以取得收益为条件；阻塞仓库仍在分母与状态表内。结论只覆盖这两个冻结仓、题集及现有 Rust／Python 能力。


## 7. 本轮结果

详见 [G4 结果与遗留项](G4_VALIDATION_REPORT.md) 和 [机器报告](archive/g4-validation/README.md "包内：knowledge/reports/g4/run-5/report.json")。

- 两仓都通过严格 ready 与重开检查：ripgrep 102 个来源；requests 35 个来源，另有 1 个空文件按原规则排除。
- zg 冻结视图完成 42 次调用，33 次通过预期核对；外部仓完成 458 次评分调用，另有 1 次不计证据分的公开引用目标定位。
- Augment 必需证据完整覆盖率平均提高 11.1／18.8 个百分点；普通结果保持一致。Constrain 的 80 次处理臂调用未观察到可见正文或元数据越界，完整覆盖率未提高；ripgrep 的证据字节覆盖率提高约 19.5 个百分点。
- 结构化契约核对 38／48 通过；另外 5 题受输出预算限制，5 题有标注假设问题。标注和失败保持原样，不以标注问题判定产品缺陷。
- 所有新增评测和格式检查、23 项图事实回归及四入口一致性检查通过。产品 Rust、原生源码、协议和依赖锁未改。
- macOS 解包位置的候选启动仍受 SIGKILL 影响；正式运行使用与包内二进制和运行库 SHA-256 相同的原构建位置，不宣称验证了解包启动。

这里只报告两仓开发题上的观察，不作全图精确率、Agent 成功率、八语言能力或普遍收益结论。后续先以新输入版本修正类型定位和引用位置标注，独立排查 zg 的相对导入／两跳缺失；不回改本轮结果。
