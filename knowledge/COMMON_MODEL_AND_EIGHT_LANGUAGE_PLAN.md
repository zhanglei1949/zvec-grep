# 公共模型与代码图实施计划（本阶段六语言）

本文件保留类型归属、来源维护、语言范围及验收设计。M0—M4、M6 的本地功能已完成；M5 跳过，M7 总体成本门禁未通过，成本优化暂缓。Q0—Q4、四语言 R0—R5 及后续正确性修复已完成，当前效果和剩余工作以 [S2 验收矩阵](S2_ACCEPTANCE_MATRIX.md)为准。

设计执行依据为两份语雀文档的 2026-10-29 版本；2026-11-02 更新要求已在矩阵登记，不倒推为已实现。后续先继续收敛查询证据缺口，再进入业务 Schema、文档结构查询与自动语义抽取；JS／TS 仍是八语言缺口。查询评测保持模型、普通排序／配额、默认预算和输出契约，真实超预算明确退化，构建耗时／RSS／磁盘优化继续暂缓。

## 目标与边界

交付两个可分别验收的成果：

1. 公共模型可真实构建、持久化、重开、查询和按来源维护，覆盖 SourceNode、SemanticEntity、Episode、Fact、来源关联及明确的事实更正。不能只交付类型声明或空表。
2. 本阶段 C、C++、Go、Java、Python、Rust 在同一模型和查询链路下支持符号定位、已确认的静态调用、导入依赖、调用／导入引用和有界路径；适用语言支持显式继承／实现关系。JavaScript／TypeScript 按用户决定跳过，仍保留为原 S2 八语言目标的缺口。

公共模型用受控的结构化输入和真实 graphdb 测试验证。文档自动语义抽取、文档产品查询、可选业务 Schema 的抽取指导与完整校验、文档代码关联、Agent memory 产品原型、第二宿主及公开发布验收由后续阶段交付。本阶段实现 Episode、事实状态和更正基础，不增加记忆管理产品流程。

继续使用完整候选构建。来源范围替换必须语义正确，但不承诺原地图 delta、upsert 或 500 ms 单文件维护；不引入 AP 装载、新存储抽象、语言服务器、通用 SDK、可选 `KgService::query` 或场景专用查询引擎。

## 公共契约

### 类型归属与复用

现有代码图模型、来源版本、正文映射、读取视图和发布约束继续沿用。M1 先按以下归属收敛，不以名称不同为由新增同义结构：

| 对象或职责 | 类型归属与处理 |
| --- | --- |
| 图查询的节点引用、定位、关系种类、视图、证据、预算、请求及结果 | 以 `zg-knowledge` 现有定义为单一来源，engine 公开路径重导出同一类型；共享默认值及结构校验 |
| engine 的工作区路径、刷新、取消、锁等待、图启用策略与可用能力 | 保留 engine 入口配置及服务检查；通用 KG 输入有效不等于当前宿主支持该能力 |
| engine Entity／Fragment、FileRecord、Range、CodeMetadata | 保留宿主检索模型；KG 通过已有 TextMap、BoundFileFacts 和绑定快照关联，不接管正文／向量，不将宿主 EntityId 当图节点身份 |
| FactNode／FileFacts、EntityRecord 与图数据库行 | 沿用抽取输入、业务读取投影和物理存储各自职责；SourceNode 是现有来源节点的目标概念，不另建第三份同义 Rust 节点模型 |
| CLI、MCP、daemon | 复用 engine 的公开类型；只保留参数／协议包装，不新增业务模型副本 |
| SemanticEntity、Episode、语义 Fact、来源支持及更正 | 只补当前缺失部分，归属 KG；复用已有位置、证据、版本与校验基础 |

复用现有 `zg-knowledge` 纯 Rust 类型不启用 graphdb；engine 的图实现仍由 feature 控制。不新增契约 crate、适配器注册框架或另一套序列化中转。能够传递同一类型的调用使用直接传值，必要的产品投影保留显式转换。

### M1 实施与验收顺序

1. **M1.1 归属核对**：记录保留、共享、投影和新增清单；冻结现有公开 JSON schema、默认预算和请求／结果样例。不能把宿主来源快照、正文实体和图节点按同名直接合并。
2. **M1.2 重复收敛**：共享现有查询契约、默认值和结构校验，移除 engine 中相同结构及无必要的 JSON 往返。服务能力和宿主参数检查继续由 engine 承担。验收要求 schema／序列化样例不变，默认及图 feature 编译与受影响回归通过，默认构建不引入 graphdb。
3. **M1.3 缺口补齐**：基于收敛后的类型补语义身份、Episode、事实状态、来源支持、更正及结构化输入，验证身份隔离、归并歧义、状态转换、JSON 对象和输入缺省／删除区别的正反例。给出字段到目标 DDL 的对应及版本变更清单。

M1.3 不宣称存储已支持新模型；M2 接入真实持久化后，才以 C01—C06 验收来源维护和重开。M1.2 当时保持外部 schema、协议 14 和存储 v4；M2.2 接入真实存储后已显式激活 v5，公开 schema 与协议 14 保持不变。

### M2 来源变更与历史边界

M2 保存和维护当前图中的语义数据，复用现有来源扫描、结构化输入、完整候选构建、导入和发布流程。必要的更正／退出记录作为当前数据库中的普通业务数据保存，不依赖 graphdb 保留旧 MVCC 版本。

| 变更 | 谁触发和确认 | KG 负责的处理 |
| --- | --- | --- |
| 本地文件新增、修改、移除或显式来源选择调整 | 用户、编辑器、Git 或扫描配置改变来源；zg-engine 在下一次索引／刷新中对比所管理范围的来源清单和版本 | 按宿主确认的来源变更构建候选；KG 不自行监听文件，也不删除原文件 |
| 外部文档新增、换版或删除 | 将来的文档接入方／同步程序确认变化并提交固定来源版本；M2 使用受控结构化输入验收，不新增同步器 | 应用明确的来源变更，不把本次请求未携带的文档当作已删除 |
| 同一来源补充或替换语义结果 | 宿主构建流程提交来源版本、update_scope 和 Complete／Partial／Failed 状态 | 核验范围、来源和完整度；仅完整成功结果替换对应贡献，缺省、部分或失败不清空 |
| 事实整体替代／撤回，或 Episode 退出 | 接入应用／其操作者提交明确指令；事实更正指定目标、上下文和预期状态 | 核验冲突，更新事实或记录状态并保存必要依据；不根据新旧文档的时间顺序自行判断谁正确 |

`SourceChange::Delete` 表示宿主明确确认的来源移除。扫描失败、单次文件读取失败、超时及不完整的来源清单不能推断删除；宿主只在成功核对其管理范围后生成删除变更。删除来源只撤销它的贡献，不等于整体撤回共享事实，也不代表物理清除历史或原文。

**当前来源维护**保存当前有效的来源版本、实体／事实支持关联和来源内结构。来源换版或删除后撤销对应贡献，保留范围外数据及其他来源的支持；全部支持消失时，事实退出默认查询。普通来源变更不要求追加完整的贡献变更流水，也不自动替代其他来源的事实。

仅因失去支持而不可见的普通事实，后续获得有效来源支持时按当前状态重新判断可见性；已被明确替代／撤回的事实不因此恢复。

**必要的业务更正与退出记录**保留被明确替代／撤回事实的 ID、内容与属性、状态、前序关联、变更时间、触发来源及其版本；Episode 保留稳定身份、退出状态及既有正文引用。F2 明确替代 F1 后，两条记录同时保存在当前图中，F1 为 superseded；F2 的支持来源撤销后，不自动恢复 F1。来源撤销所需的退出状态和出处也须保留，以防重放错误地重新激活；不要求保存该来源的每一版完整内容和全部贡献快照。

KG 保存来源标识、版本及可选定位；正文和向量仍由宿主管理，M2 不新增逐版全文／向量副本或归档系统。读取历史依据时核验宿主保留的正文；不可读或版本不匹配时明确报告证据不可用，不返回新正文或失配偏移。

**完整多版本图不在范围内**：不增加任意时点的全图查询、按历史构建选择完整快照的接口、数据库级时间旅行或全量事件溯源。MVCC 只承担事务并发与一致性；旧读者、旧候选的保留和回收继续遵循现有生命周期，不作为业务历史存储机制。M3 的“历史查询”仅指在所选当前图内显式读取这些业务更正／退出记录。

### 身份与来源

| 对象 | 本阶段确定的约束 |
| --- | --- |
| SourceId／SourceRef | SourceId 在宿主知识库内标识来源，SourceRef 固定其版本。文件来源继续使用规范化路径和原始／解码摘要校验；公共来源身份与文件路径校验分开，Episode 不冒充源码文件 |
| SourceNode | 归属一个来源，保存类型、名称及文本来源的 UTF-8 半开区间。NodeId 独立于检索 EntityId，不承诺跨编辑稳定；CONTAINS 保留同来源直接父子关系 |
| SemanticEntity | `(space_id, id)` 跨候选构建稳定。zg 默认身份空间绑定工作区的持久化知识库身份，不绑定存储 generation；跨工作区共享须显式指定，不默认归并 |
| 身份归并 | 业务 ID 优先；没有业务 ID 时，按同空间、类型、名称及别名规则匹配，唯一且无冲突才归并并保留依据。多义返回候选，相关事实不能声明成功；代码符号与同名业务实体不自动合并 |
| Episode | 保存稳定 ID、空间、固定来源版本、上下文、发生／接入时间、正文引用及 active／withdrawn 状态。正文与向量仍归宿主，退出后保留必要记录，不复制完整图快照 |
| Fact | 保存稳定 ID、有类型主体、实体或标量对象、predicate、context、状态及 supersedes。默认只查询当前有效且有可用来源的事实；更正记录保存在当前图，历史读取须显式请求 |
| 附加属性 | 输入区分缺省与显式提交；存储为 JSON 对象字符串。身份、predicate、状态、更正和来源独立存储。缺省不清空已有属性；冲突不静默合并，事实属性更正保留旧记录 |
| 来源关联 | 固定实体或事实的类型、空间、ID、SourceRef、支持／更正用途及可选定位。撤销一个来源不删除其他来源仍支持的实体或事实 |

新生成的语义实体、事实及 Episode ID 在成功候选中落盘，并在后续范围替换、重开和重建中继承；不能仅按名称重新生成身份。归并规则及其版本属于构建依赖。

### 存储与更新

- 采用固定的 SourceNode、SemanticEntity、Episode 业务点与 CONTAINS、CALLS、IMPORTS、LINKS、EXTENDS、IMPLEMENTS、MENTIONS、SEMANTIC_RELATION 关系。实体间事实直接保存为 SEMANTIC_RELATION 边，predicate 保存业务名称；不为每种业务关系建表，不新增 Fact 业务点。标量事实历史使用固定辅助记录。
- UnresolvedRef、来源关联、作用域、构建清单、Root／Receipt 等辅助数据不参与业务路径。一个 ref_id 在同一构建中只对应一条已解析边或一个未解析记录；重复调用、自递归及各提及位置分别保留。
- `update_scope` 明确替换来源。范围外数据继承基图，受影响的范围外引用仍须重算。只有成功且完整的空输入才能清空该部分贡献；缺省、失败、部分完成及删除分别表达。
- 相同语义事实只有在主体、predicate、对象、上下文、附加属性及已声明规则兼容时才累计来源，不统一按三元组去重；未配置业务定义时不推断单值关系，不自动覆盖不同事实。
- 明确替代／撤回由接入方触发，须核验目标、上下文与预期状态；旧状态、新事实和更正关联通过同一候选的提交与发布一起生效。文档冲突不按最后写入覆盖；无可用来源的事实退出默认查询，已替代／撤回事实不因重放重新激活。
- 保留导入后确认、提交前核验、Root／Receipt 原子提交及提交后独立只读确认。宿主发布与图内提交分别判断，发布复查和版本选择仍受同一并发控制保护。

### 查询与兼容

沿用现有固定视图、`explore`、`augment`、`resolve_scope` 职责。有类型对象引用必须区分 SourceNode、SemanticEntity、Episode 与 Fact，并绑定图构建版本；语义查询支持 kind、predicate、当前／历史状态及来源追溯，JSON 属性只携带和返回，不增加任意属性查询语言。

这里的历史状态限定为所选当前图中保存的业务更正／退出记录，不提供任意过去时点或旧构建的完整图查询。

视图固定身份空间、来源／上下文范围、事实状态及宿主授权的交集。共享实体不能把不可见来源带入结果；历史选项不扩大权限。结构、语义和正文就绪分别检查，所需状态无法核验即失败。上述约束也适用于 Off、缓存命中及退化路径。

M2／M3 接入公共模型将改变当前物理 Schema、事实格式和部分查询契约。M1 确定目标版本及变更清单，M2.2 已激活 v5，M2.3 来源退出及失效提及使用 v6，M2.4—M2.5 更正及尝试记录激活 v7；不再声称 v4 摘要字节不变。v4 代码图通过显式重建升级，查询不补写；保留旧格式拒绝用例。既有代码请求的语义尽量保持，必要的 wire 变化同步升级 daemon 协议、能力标识和 MCP schema，旧端明确拒绝，不静默丢字段。

## 语言接入范围

正文分段已有八语言 Tree-sitter 适配器；KG 的 Language、事实抽取和模块映射现支持 Rust、Python、Go、Java、C、C++ 的声明范围。JS／TS 代码图本阶段跳过，正文检索沿用现有能力。复用同次 AST、解码文本和检索实体绑定，不另起一次解析或以分段支持冒充代码图支持。语言配置和语法版本纳入规则指纹。

| 顺序／语言 | 最低正向范围 | 显式类型关系 | 必须保持诊断的边界 |
| --- | --- | --- | --- |
| 既有 Rust | 模块、函数、类型、固有方法、use／重导出及可证明的静态调用 | trait 的显式父 trait → EXTENDS；具体类型的显式 trait impl → IMPLEMENTS | 动态派发、宏展开、无法证明的泛型／条件 impl 和重载式歧义不推断 |
| 既有 Python | 模块、类、函数、方法声明、导入及已确认的词法静态调用 | 显式且唯一解析的基类 → EXTENDS | 动态赋值、装饰器改变目标、未知接收者与元类不猜测；不推断 Protocol 实现 |
| Go | package、类型、函数、方法声明、别名导入、同包及限定包静态调用 | 不推断隐式接口实现；嵌入保留声明／结构证据，不伪造类继承 | 接口派发、未知接收者、构建条件冲突和外部包保留诊断 |
| Java | package、类、接口、方法、字段、import 及可唯一证明的静态调用 | class／interface extends、class implements | 无法确认的重载、虚派发、反射、外部 classpath 不猜测 |
| JavaScript | 模块、函数、类、方法、ESM 导入／导出及静态字符串 CJS 的支持子集 | class extends | 动态 require／import、原型运行时修改、未知接收者不执行或推断 |
| TypeScript | JS 基础加 interface、类型声明、显式类型导入及路径映射支持子集 | class／interface extends、class implements | 类型擦除不产生 CALLS；复杂类型推导、装饰器及动态目标不推断 |
| C | 文件、函数、结构体／字段、明确 include、受可见性及编译单元约束的静态调用 | 不适用 | 函数指针、宏生成调用、条件编译不明、跨链接单元同名目标不猜测 |
| C++ | C 基础加 namespace、类、方法、明确限定调用与 include | 单／多基类声明 → EXTENDS；不另造 IMPLEMENTS | 虚派发、未知接收者、重载、模板实例化及不明链接范围不推断 |

“不适用”按语言语义记录，不伪造边，也不记为该语言类型关系实现通过。跨语言解析只开放有明确规则和来源证据的情况；除本批次明确支持的 JS/TS 模块外，其余语言边界不通过同名匹配连边。

扩展名按设计第 5.1 节与现有格式目录逐项核验：保留 `.C`／`.c`、`.H`／`.h` 大小写；最长后缀识别 `.d.ts`／`.d.cts`／`.d.mts`；`.tsx` 使用 TSX grammar。`.h` 根据关联编译单元或显式项目配置判断 C/C++，无法确定就报告来源诊断，不沿用“优先 C++”作为正确性证明。

`compile_commands.json`、`jsconfig.json`、`tsconfig*.json` 只在对应语言批次实现所需字段及明确的支持子集；Go 模块路径需要时读取 `go.mod`。配置缺失允许基础建图，依赖配置才能确定的关系保留诊断；无效、不支持或相互冲突的已使用配置明确报告。配置不建符号节点，不运行命令，所读配置及其变化进入构建依赖，触发必要的重新解析和文本映射核验。

## 公共模型验收

使用固定结构化输入、宿主正文引用和真实原生数据库。M2 先通过存储读取验证身份、状态和来源维护；M3 再通过统一查询核对这些数据的可见性与证据，完成以下全部验收。纯内存单测作为补充。

下表的历史均指当前图内必要的更正／退出记录；不要求 graphdb 保留可按时间查询的旧图版本。来源变更由宿主确认并提交，KG 不从缺省或失败输入推断删除。

| 编号 | 必须通过的断言 |
| --- | --- |
| C01 固定模型 | 三类业务点、八类业务关系及必要辅助记录真实往返；新增两个 kind／predicate 不产生新表列。JSON 数值／布尔／数组类型往返保留，非对象属性、公共字段覆盖、非法端点与区间被拒绝 |
| C02 身份 | 同空间业务 ID 跨版本复用；同名不同空间、不同类型及源码符号不误合并；多义返回候选。重复构建、来源范围替换及重开不改变既有实体、事实和 Episode 身份 |
| C03 当前来源维护 | 两个来源支持同一事实；宿主明确撤销一个后仍可查询，撤销全部退出默认查询，并保留必要退出／更正状态及出处。来源删除不等于整体撤回事实，普通文档冲突不自动触发替代。代码范围全量重建保留范围外语义／Episode 数据；不误删共享实体 |
| C04 更正与重放 | 接入方明确提交 F2 替代 F1，当前图保存两条记录、状态、前序、时间和触发来源；默认只返回有效且仍有支持的 F2。撤销 F2 来源后不复活 F1，已撤回事实不因重放复活。释放旧读者并关闭重开后记录仍正确；预期状态及属性冲突显式拒绝，失败不留下半条更正链 |
| C05 触发与变更含义 | 文件移除经宿主来源核对，语义来源删除和事实更正由接入方显式提交；未携带、扫描／读取失败或超时不当作删除。完整空集、缺省、部分、失败和删除分别验证；缺省属性不清空，范围外数据继承。相同 operation／attempt 重放幂等，不同输入报冲突；陈旧基图不能覆盖新发布版本 |
| C06 格式与完整性 | 新格式往返、规范摘要、计数及 Root／Receipt 一致；缺失、多余、重复和篡改数据被拒绝。v4 查询明确拒绝并可显式重建；新候选继承稳定身份及必要更正／退出记录，这些记录不依赖旧候选或旧 MVCC 版本存活 |
| C07 统一读取 | 真实 explore 夹具返回有类型对象、predicate、事实状态及来源证据；NodeRef 跨构建拒绝。当前记录／业务更正记录、空间／上下文、授权交集和来源失配分别验证；历史正文不可读或版本失配时显式返回证据不可用，不返回新正文或旧偏移。撤回 Episode 不泄入默认检索或缓存；辅助记录不增加路径跳数，不提供任意时点的完整图查询 |

MENTIONS 和引用边必须逐位置取证，语义事实经独立来源关联取证。共享实体没有自身 span 时不能猜测原文位置；来源不匹配时不返回旧偏移。对后续语义范围检索的最小夹具验证实际 TextMap／记录映射：完整空范围零模型，映射缺失或范围不完整显式失败。

## 每门语言的验收

| 编号 | 必须通过的断言 |
| --- | --- |
| L01 来源与符号 | 从宿主真实扫描清单核对必需来源、语言选择、模块映射及事实完成状态；符号类型、嵌套与 UTF-8 位置正确，覆盖中文、CRLF、BOM。配置文件不冒充源码节点 |

每项契约为每门适用语言至少准备一个正向用例及一个对应的拒绝／失效用例，附源码、独立标注和预期状态。不适用项说明语言依据。来源完整性、静态解析率和查询完成度分开统计，不能把全引用解析成功作为 ready 的条件，也不能用遍历 complete 代替来源覆盖。

## 评测与成本

- 保留原 `g4-code-v7`、`g4-code-v8`、输入、生成器和历史报告。新增独立标识的本阶段六语言评测输入及公共模型夹具，预先冻结源码提交、文件摘要、预期关系、案例角色、评分与预算；生成器不读取候选输出。
- 原 G4 v8 的 48 道结构化题和 458 次调用继续作为 Rust/Python 兼容回归，正常 43 项和预算负向 5 项分开验收。新六语言用例单列，不与旧题混合计算质量增益。
- 每门语言选择至少一个固定版本的代表性真实仓库，可由同一多语言仓库覆盖多门语言；另有混合工作区验证语言／命名空间隔离；JS/TS 仅检查能力边界，不验收代码图互通。公开证据必须匹配源码和视图。遗漏调用、版本漂移、无效证据、伪造目标、越界或把错误当空结果均阻止验收。
- 冻结用例的正常契约、负向行为与来源核验须全部通过。召回／证据增益、已标注关系准确性和各语言解析率如实报告，不要求人为制造正收益，不把未标注关系当错误或将局部结果外推为全语言精确率。
- 对固定旧 Rust/Python 切片按已有 runner 做前后三轮 graph-only 和六场景 Release 对照；新增六语言语料独立记录规模、关系数、耗时、峰值 RSS 和磁盘。输出放在索引目录之外，源码、原生库、模型和运行配置分别冻结。
- 新模型格式不同，不能要求新旧物理摘要相同；比较等价代码事实投影、关系、证据及计数，并分别验证各版本规范摘要。沿用分段耗时、完整读取次数和逐项资源门禁；默认预算超时、新的资源耗尽或随来源数反复全扫描等回退须定位处理。
- 功能验收与总体性能门禁分别给出结论。保留 500 ms、graph-only／文本成本比例、RSS 和新旧产物并存等现有未达标项；不把语言扩展或来源替换语义通过称为低成本增量完成。上轮 32.95 秒及 1,339 MiB 仅是其固定环境参考，不直接作为跨机器门槛。

验证按改动范围执行：公共模型涉及 KG 持久化、取消／回滚／恢复／发布，语言批次涉及 engine 事实与抽取，公开契约涉及 CLI／daemon／MCP 和协议，评测变更运行框架已有测试；同时检查默认 feature 和 graph feature。运行 Rust 格式、受影响 crate 严格 Clippy 及必要文档检查，不为各语言重复建立整套无关流程。
