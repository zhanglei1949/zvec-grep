# [Feature] 支持从内存批量导入数据（append / upsert）

## 诉求

希望 graphdb 提供**从内存批量导入数据**的接口，支持 **append** 与 **upsert** 两种语义。目前看代码，批量导入似乎只能通过 `COPY FROM`（面向文件），或者逐条 `INSERT`，缺少直接消费内存中数据的批量入口。

## 场景

- **从空图开始载图**：一次性把整张图灌入。
- **子图增量更新**：某些代码文件被修改后，一部分子图随之变化（可能同时包含新增 + 更新）。逐条更新 / 插入效率较低，需要批量导入。

## 实现层面的初步判断

底层能力（批量写入、端点解析等）看代码应该已经具备，主要缺的是**上层封装**与**上层行为边界定义**，这部分需要设计实现。例如：是提供独立的 **API 接口**，还是**嵌入到 Cypher 语法**里（如扩展 `COPY FROM` 支持内存数据源，或提供 upsert / `MERGE` 语义）。

## 一致性要求

- 在 zg 的场景里，构建 / 导入是一个**显式、blocking 的操作**，**阻塞其他查询是可以接受的**。
- 但**一致性需要保证**：一次批量导入**要么全部生效、要么全部不生效**（原子性），不能出现“导入了一半”的中间态。

## 待讨论

- **内存数据交换格式**：是否考虑用 **Arrow / Parquet** 等列式格式？zg 侧数据本就在内存中，若能零拷贝或低成本地以列式传入会更好。
- **append / upsert 的语义边界**：重复主键的行为；upsert 时已有属性与关联边如何处理。
